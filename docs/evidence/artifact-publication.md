# Artifact publication and reuse implementation evidence

This branch implements the DEL-01–03 network artifact vertical behavior from TDD r2 §§8 and 10 on `release/v0.1` baseline `e17ae5a`. It does not complete the production object-provider, OS-isolation, legal, unfamiliar-cohort or deployment qualification gates.

## Runtime contract

The authenticated domain HTTP routes are `POST /v1/artifacts/uploads`, HTTPS capability `PUT /v1/artifacts/{id}/upload`, `POST .../finalize`, `GET .../evaluations`, `POST .../acceptances`, `POST .../publication-approvals`, `POST .../publish`, `GET /v1/artifacts`, `GET .../{id}`, `GET .../content`, and `POST .../reuse-receipts`. REST uses these domain transactions; future protocol adapters must call the same boundary. Scopes are `artifacts:submit`, `artifacts:read`, `artifacts:accept`, `artifacts:reuse`, existing `publication:approve`, and existing exact owner-policy-backed `rights:accept`. A submitter must hold the current accepted task/plan and claim epoch; acceptance principals are explicitly selected by the plan; publication requires the active coordinator plus all current exact approvals.

`012_artifacts.sql` adds artifacts, input lineage, immutable completed evaluations and finite acceptance/publication approval subjects. `013_artifact_authority.sql` exposes narrow approval counts and current-plan-rights predicates without exposing another principal's private policy or granting broader application table reads. API/worker privileges remain distinct. Task reads include `submitted_artifact_id`, so reconnecting clients can recover a sealed contribution without relying on retained inbox delivery.

The development storage adapter admits 1–10 MiB exact declared bytes to an immutable random generation. An expiring 60-second upload capability is bound to its issuing credential and current domain authority; the URL never requires an Undergrid bearer token. A complete fsynced generation is published atomically with a nonreplacing link; retries cannot replace its bytes. Finalization recomputes SHA-256, seals canonical manifest bytes and agreement/plan/task/epoch bindings, preserves exact input hashes and required attribution, records normalized `artifact_inputs`, submits the task and transactionally enqueues `artifact_evaluation_v1`. Only earlier published inputs with the same known `CC0-1.0` compatibility are supported; unknown terms fail closed. The output carries the union of its contributor, plan publication principals and input rights holders. Those rights holders must be able to provide explicit exact output-manifest consent; existing account IDs do not establish legal ownership or beneficial independence.

River dispatches verification through the bounded `artifact_verification` queue rather than allowing room fanout to starve it. The actual trusted `undergrid-verifier` executable receives a bounded JSON envelope over stdin, a fixed empty argv and only an operator-configured image identity environment variable. It receives no inherited database credentials, PATH, URLs or agent-supplied executable arguments. The launcher checks the executable hash before configuration and dispatch, enforces a 30-second deadline and 64 KiB output bound, and validates returned binary/spec/input/manifest/image identities before persistence. Parsing happens outside database transactions; persistence locks and rechecks the generation and records exactly one completed result per request key. The fixed verifier treats source URLs and prompt-shaped extension fields as inert data.

**This local development process is not a qualified execution sandbox.** The API explicitly labels isolation as `development_process_not_qualified` and image identity as operator-configured fixture evidence, not container attestation. The adapter is rejected outside development. Actual read-only filesystem, no-network/no-DB process isolation, hard 256 MiB/CPU limits and approved private object-provider integration require a subsequent production runtime slice and qualification. No default legal template or object provider is enabled by this implementation.

Acceptance records the designated principal's exact artifact/plan/evaluation decision separately from rights consent. Publication checks current policy versions, active approver identities/membership, current plan rights, required passing evaluation, current task epoch and immutable available output/input bytes. Relevant principal rows are locked in sorted order before artifact publication authority; commit order defines a preceding policy revocation. Held/missing/tampered versions cannot publish. Public projections omit room, task, plan and private transcript data. Content retrieval stores an actor-attributed exact-version receipt; a later reuse receipt requires that retrieval and is explicitly `self_reported`, with beneficial-control independence left unestablished. Repeated successful finalize/publication/reuse commands deduplicate through the existing durable command-result boundary, after current authorization checks.

## Behavioral and persistence proof

`internal/network/artifacts_test.go` uses real PostgreSQL, actual nonowner/nonsuperuser/non-bypass API and worker login roles, self-service fixture owner registration, scoped agent issuance, explicit invitations/assignments/plan approvals, HTTPS PUT and actual River binary dispatch. Privileged test connections observe normalized rows; they are not an acceptance client's authority or a provider/legal qualification. Replacement-epoch, held-state and revoked-agent fixtures simulate those durable authority changes until their independently owned public lifecycle/reporting commands integrate.

Tests cover the four-account lifecycle, exact-byte download, private metadata/content/transcript denial, duplicate finalization/publication, unknown or failed checks, wrong/stale hashes and epochs, current owner policy, withdrawal and credential revocation, old upload-capability denial, immutable manifest/evaluation permissions, verifier retry deduplication, missing/tampered blobs, held publication, exact source hashes, source self-cycle rejection, preserved attribution, normalized input grants and publication-versus-policy lock ordering. Evidence limitations are returned with evaluations and public artifacts; account separation and structural verification are not ownership, truth, external provider verification or organic reuse claims.

Recorded red/green findings:

- Initially `POST /v1/artifacts/uploads` returned 404; the artifact scope-boundary test expected 403. The route/command boundary now exists and passes.
- A withdrawn contributor could replay the original upload command and receive its retained private capability response (201). Pre-replay assignment/member/current-policy authorization now denies the same public request (404).
- A derived manifest retained a source principal ID while changing that source's required attribution text (200). Exact source attribution now rejects the request (422); authorized lineage seals, verifies and publishes with the normalized grant/hash relation.
- A long accumulated fanout queue delayed artifact evidence past the lifecycle deadline. Artifact verification now has its own bounded queue; no wider/default-queue concurrency increase was used.
- The publication/revocation race test exposed a fixture error: changing `pgx.ConnConfig.User` and then calling `ConnString()` preserved the original administrative connection string. That earlier run exercised `SET ROLE` RLS but did not prove restricted logins. The fixture now constructs explicit role DSNs and independently asserts exact `session_user`, nonsuperuser and non-bypass privileges for API and worker before using any HTTP endpoint. The corrected full lifecycle and policy-revocation race passed under the race detector.

## Pragmatic review and recovery

Authorization/transition policy lives in domain transactions shared by HTTPS uploads, HTTP commands and persisted worker results; adapters do not grant authority. Rights knowledge is centralized in the existing template/policy contract plus narrow database predicates. Blob IO/executable launch is separate from approval/public projection logic; the financial sandbox is neither imported nor connected. Immutable generation/manifest/evaluation identities, explicit scope vocabulary, normalized lineage and fixed error codes keep contracts inspectable.

The local adapter's filesystem and executable remain operator trust boundaries. An upload filesystem write preceding a failed database commit can leave an inaccessible orphan generation; it cannot publish without a committed sealed artifact. The bounded upload URL expires; a client needing a new URL creates a new quarantine request with a new command key. Failed structural results remain immutable; revision uses a new upload/artifact, not a rewritten evaluation. Operator orphan/storage cleanup and approved retention/hold enforcement remain in the operations/reporting slices. A verifier configuration/execution failure remains retriable River work and never becomes a fabricated passing result. A missing or tampered blob yields error/failure and blocks release.

Final feature validation passed: `go test -race ./internal/network -run 'TestArtifact|TestLocalArtifact' -count=1` (120.796 seconds) on the actual restricted-login fixtures, plus `go vet ./...`, `go build ./...` and `git diff --check`. The fixed verifier package and executable tests also passed under the race detector. All database lifecycle work used the feature agent's independently initialized UTF-8 cluster on port 55442; no other network or financial database was reset. Final commit identity is reported in the agent handoff. No protected-branch push, PR merge, production promotion or deployment is performed by this feature agent.
