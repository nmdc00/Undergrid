# Sandbox refund authority

Implements TDD §11.2 refund authority and lifecycle through POST `/v1/refunds`, GET `/v1/refunds/{id}`, POST `/v1/refunds/{id}/authorize`, worker `BeginRefundDispatch`/`MarkRefundUnknown`, and internal verified-effect reconciliation. Every response carries the permanent TEST designation. No provider request or real Stripe qualification is claimed.

Owner policy must explicitly permit refunds; credential request/authorization scopes are separate from purchase authority and refund reading. Exact refund hashes bind actor, credential, original payment/hash, amount and nonce. Actor-first transaction locks serialize reservations against verified refundable charges. Pending/unknown refunds retain capacity; verified refunds never replenish the gross purchase cap. Revoked credentials and changed policy are checked before dispatch, while valid late monetary facts remain recordable after revocation. Stable provider keys cannot be replaced on unknown outcomes.

Red evidence: the new HTTP request test returned 404 before routes existed; the later domain lifecycle tests failed to compile because the refund entrypoints did not exist. An additional read-only credential test exposed an overly broad refund-policy requirement, corrected so reading does not grant spending authority. The retry-metadata privacy assertion is a passing regression, not a claimed observed red.

Green evidence: `go test -race ./internal/sandbox ./cmd/undergrid-sandbox -count=1` passed against fresh migrated financial database `undergrid_sandbox_refunds`, restricted application/worker roles and a separate network database. Tests exercise exact retry/conflicting body, cross-actor denial, absent owner grant, wrong hash, concurrent over-refund prevention, unknown/no redispatch, late reconciliation/replay after revocation, unchanged gross spending cap, pre-dispatch revocation and row-level retry privacy. `go vet ./...` and `go build ./...` passed. All-package race tests passed for network/identity/verification; an erroneous duplicate post-revocation test assertion was corrected before the financial suite passed.

Quality assessment: purchase and refund lifecycles remain independent aggregates; shared actor policy, scope authentication, transaction handling and verified monetary facts reuse existing domain contracts. Composite ownership foreign keys and RLS protect refund identity and retry metadata. Refund reservation accounting counts succeeded effects once and unresolved authority once. Provider reconciliation is internal and deliberately accepts late verified facts without reauthorizing them. Migration 001 remains immutable; versioned migrations 002/003 add the new contract.

Remaining work: actual trusted provider dispatch and object verification, signed receipt projections, bounded subscriptions and financial UI are separate behaviors. Fixture evidence uses `verified_by: fixture`, not provider verification. Legal/provider configuration and actual test-account qualification remain explicit release gates.
