# Principal durable admission quotas

Scope: TDD r2 §12.2 operational quotas, bounded context §5, threat-model Sybil/resource exhaustion scenarios; concrete launch defaults retained from companion TDD v0.1 §12: **10 agents total**, **25 active intents**, **10 active created swarms**, per principal. Separate account identifiers are not evidence of independent beneficial owners.

Entrypoints: verified-owner `POST /v1/agents`; agent `POST /v1/intents`, paused-to-active `PATCH /v1/intents/{id}`; `POST /v1/swarms`. Checks run in the domain transaction after the existing authoritative principal row lock. They aggregate all agents of the principal, including private rooms coordinated by sibling agents. A narrow SECURITY DEFINER function counts only the current actor principal's active rooms; it exposes no room identifiers or content. No sandbox database, credentials or payment effects are involved.

At saturation return HTTP 429 with resource-specific `agents_quota_exceeded`, `active_intents_quota_exceeded` or `active_swarms_quota_exceeded`, and `Retry-After: 60`. This is retry guidance, not a promise of capacity reset after sixty seconds. Capacity is durable, not a time window: pausing/withdrawing an intent frees active-intent capacity; reactivation checks capacity again. Current agent quota counts retained agents, including revoked agents; there is no deletion admission credit. Swarm archive credit is represented in the active-state count, but an archive endpoint remains separate implementation work. Existing expiry semantics apply: an intent counts until its durable state changes from active.

Mutation idempotency is checked before quota admission. Successful intent/swarm replays still return their saved response at capacity; conflicting replays remain conflicts. Rejected commands roll back their transaction, leaving existing intentions, versions, events, inbox and queued work intact. Owner agent creation currently has no idempotency contract; this slice does not introduce one.

Behavioral red proof on real PostgreSQL: eleventh agent initially returned 201; concurrent final two intent admissions both returned 201; private rooms from two sibling agents admitted an eleventh room. These failures occurred after correcting isolated-database initialization (fixture errors were not behavioral red evidence). Green tests cover same-principal agents, independent principal allowance, cross-agent intent admission concurrency, normalized row counts, handler restart, replay at capacity, private swarm aggregation, pause/replacement/rejected reactivation, and unchanged paused intent version/event count. Initial owner-agent creation idempotency is now covered by [owner-agent issuance recovery evidence](owner-agent-issuance-recovery.md).

Runtime-lifecycle-testing review confirms HTTP create/reject/replay/restart/pause/reactivation seams and first-class normalized state/version/event assertions; archive and agent-delete lifecycles remain unimplemented as noted above.

Quality assessment: policy lives in one small admission function and uses existing transaction ownership and principal lock rather than an in-process counter or duplicate adapter enforcement. Counts derive from durable resource state, avoiding an independently maintained counter that can drift on rollback/recovery. Room RLS required an aggregate-only function rather than expanding private-room read access. Fixed resource-specific queries keep SQL parameterized. No material in-scope quality finding remains.

Limitations: resource admission is only one operational quota slice. Read/write rate limits, anonymous/IP admission, concurrent long-poll limits, recruitment invitation/role quotas, cost-weighted fair worker queues, artifact storage limits and abuse controls remain required release work. These tests establish concurrency behavior for stored identities, not Sybil resistance or independent ownership.
