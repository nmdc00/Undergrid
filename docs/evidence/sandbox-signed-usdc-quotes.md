# Signed TEST USDC quotes

TDD §§11.2/11.4, financial migration009. Initial implementation741d8a6; SQL NULL oracle hardening8582ebd; final key/catalog/nonce correction05669fe. Local feature branch only; remote review/promotion/deployment pending.

The existing POST `/v1/payments` accepts only a catalog product. A configured USDC/x402_test offer creates an immutable signed envelope binding financial actor and credential, payment ID/nonce, original owner-proven EOA wallet binding ID/epoch/payer, configured payee, atomic amount and fee, terms ID/hash, expiry, Base Sepolia84532 and native Circle USDC `0x036cbd53842c5426634e7929541ec2318f3dcf7e`. The designation is TEST. Payment responses expose `signed_quote` with key ID and base64 payload/signature; clients verify the exact decoded payload bytes with Ed25519. `quote_hash` is SHA256 of those bytes. The signed nonce is a stable lowercase `0x`-prefixed bytes32 value: SHA256 of `undergrid-usdc-quote-nonce-v1:` plus the cryptographically random payment UUID. Distinct payment IDs generate distinct opaque nonce commitments; retries preserve them. This does not prove EIP-3009 transfer authorization or external chain execution.

GET and idempotent retry/restart recover the exact persisted bytes. Authorization verifies the signature, signed payload against persisted identity/quote, current credential/policy and current owner wallet epoch under the existing actor transaction lock. Worker dispatch checks the same domain contract under that lock. Rebinding cancels undispatched authorized authority and blocks authorization of older quotes. A submitting/unknown attempt retains its original envelope, provider key, state and reservation; redispatch is rejected and original command replay cannot create a replacement charge. Existing Stripe dispatch explicitly rejects the USDC rail before any provider call.

Startup USDC catalog configuration requires `UNDERGRID_SANDBOX_USDC_SIGNING_KEY_ID`, `UNDERGRID_SANDBOX_USDC_SIGNING_PRIVATE_KEY` (base64 64-byte Ed25519 private key), and `UNDERGRID_SANDBOX_USDC_SIGNING_PUBLIC_KEYS` (JSON key-ID→base64 32-byte public-key map). The private key must reproduce exactly from its own seed, and its embedded public key must match the selected public configuration; explicitly configured historical public keys verify persisted older quotes. No keys are generated automatically. The TEST catalog admits at most one Stripe product and one USDC resource (two total); USDC payees use normalized lowercase Ethereum addresses. Owner spend policy explicitly selects USD or USDC with integer atomic limits; there is no FX conversion.

## Pragmatic review and remaining scope

Envelope serialization belongs to one financial-domain helper; creation, authorization and dispatch share it while the public-key test verifies independently. Existing actor locks, credentials, idempotency and reservation aggregate remain authoritative. SQL constraints and an immutable quote trigger defend persisted contracts independently of HTTP. Database failures propagate rather than being mistaken for authority denial/cancellation. Trusted key bytes are copied; unknown key IDs fail closed without cryptographic panics. No network repository, generic payment framework, future empty tables or agent execution was introduced.

This proves signed quote/authority fixture behavior, not x402 settlement. Actual chain/token deployment and six-decimal checks, external wallet/facilitator/provider approval, canonical nonce→transaction binding, receipt/finality/reorg evidence, recipient-authorized external refunds and production deployment remain unqualified or unimplemented subsequent slices. No facilitator/RPC call, wallet custody or paid label is added.
