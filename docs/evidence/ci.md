# Continuous integration qualification

Current owner policy (2026-10-13): GitHub-hosted CI is not required. Its workflow is disabled in repository settings and required status checks were removed from the protected branches, retaining PR and force-push controls. The workflow file remains a reproducible test recipe. Local lifecycle/race/static/build checks still gate integration; this change does not waive application tests or provider/deployment approvals.

Scope: TDD r2 section 12.2 and N6 preparation. `.github/workflows/ci.yml` runs the actual Go/PostgreSQL test suite, static checks, formatting, module integrity, command builds and the separately labeled reference-listener tests. Network and sandbox databases are distinct. Migration-test credentials are disposable superuser credentials on the ephemeral CI service; application-path tests explicitly assume restricted roles. This is not evidence that deployed runtime credentials are restricted.

GitHub Actions checkout and setup-go are pinned to resolved commit IDs, with read-only repository permissions and credential persistence disabled. The workflow uses ordinary pull-request events, not privileged `pull_request_target`. No provider, deployment, cloud or production secrets are injected. Sources checked: [checkout](https://github.com/actions/checkout), [setup-go](https://github.com/actions/setup-go), [PostgreSQL services](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers). PostgreSQL uses a version tag for this disposable test service; production images must be digest pinned and qualified separately.

This was an account-level failure before application tests ran. The owner subsequently waived hosted CI and authorized PR merging using reviewed local evidence. Hosted execution remains unverified; no passing hosted result is claimed. Local test evidence is recorded separately per feature. Hosted race tests and service bootstrap remain unverified until this workflow actually runs. Green local-system CI does not replace provider-test receipts, production restore/security drills, protocol conformance, or an unfamiliar external cohort.

Quality assessment: CI calls existing package tests and commands rather than duplicating domain assertions in shell. Financial isolation is expressed through separate databases, not a shared privileged domain fixture. The job deliberately fails on test failure and has no skipped-test fallback or continue-on-error setting. Deployment automation and vulnerability scanning are not claimed by this slice.
