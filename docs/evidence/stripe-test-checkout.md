# Stripe TEST Checkout and reconciliation

Implements TDD §11.3's server-selected test Checkout, signed durable event inbox, canonical object reconciliation and partial refund path. `undergrid-sandbox -mode stripe-worker` uses a dedicated worker-only financial database login and separate provider credentials. API startup rejects provider-worker secrets. The API reads `checkout_url` from the payment after the worker creates its bound session; browser redirects never settle a purchase.

The official Stripe Go SDK is pinned at v87.0.0 / API `2026-09-30.endive`. Production configuration uses the fixed Stripe API endpoint, test-key prefix, exact verified platform account, fixed product/price and HTTPS return URLs. Automatic tax, adaptive pricing, discounts and arbitrary line items are disabled. Verified price currency/product/amount must match the immutable quote. The authority claim commits before any creation request, uses the original provider idempotency key, and disables SDK creation retries. Failed or lost responses retain unknown reservations; bounded object searches reconcile the original identity without posting again. Subscription reservations are excluded from this Checkout dispatcher because they require a separate controlled invoice-collection contract.

POST `/v1/provider/stripe/events` verifies the untouched raw body with the SDK's signed timestamp/version contract, rejects live/cross-account/version mismatches and acknowledges only after durable deduped storage. A matching event ID with changed raw bytes conflicts. Event data supplies only an object ID. The worker retrieves canonical charge/refund/Checkout/canceled-intent objects under the configured account key, checks exact asset/amount/hash/payment and consent bindings, then applies append-only facts or conditional terminal transitions. Late valid refund facts survive revocation. Unknown refunds never redispatch. Unsupported or mismatched events remain blocked; transient object retrieval has ten bounded attempts and requires later operator review rather than weakening verification.

Quality assessment: HTTP intake, provider calls and domain financial transactions have separate responsibilities. Actor-first authority locking and existing verified-effect reconciliation remain shared contracts; refunds retain their independent state and exact consent. Durable webhook bytes are not accepted as monetary truth. Provider creation never occurs inside database transactions. Public errors and persisted failure categories omit provider payloads; the production SDK logger is disabled. Immutable inbox body/hash fields are not update-granted. The worker stays bounded per tick and cancellation-aware. Fair scheduling/operator dead-letter alerts and signed receipts remain distinct work items.

Runbook: provision a worker-only nonowner login on the financial database; migrate with the separate migrator; configure only `.env.sandbox-worker.example` for this process and only `.env.sandbox.example` for the owner API. Configure the approved Stripe TEST webhook endpoint at the pinned API version for `charge.succeeded`, `refund.created`, `refund.updated`, `refund.failed`, `checkout.session.completed`, `checkout.session.async_payment_succeeded` and `payment_intent.canceled`. Expose the worker's webhook through the approved TLS deployment; it binds localhost:8082 by default. Never install live keys, enable automatic subscription collection or resend a creation after unknown results. Inspect blocked inbox rows through the operator identity; restoration/alerting/provider credential qualification still gate deployment.
