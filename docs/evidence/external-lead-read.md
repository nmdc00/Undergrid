# Intention-scoped external lead retrieval

TDD §§5.2–5.4/9. This vertical implements safe, current-authorized retrieval of permissioned external metadata. It does **not** complete first-user relevance/fit reports, complementary or semantic ranking, persisted external opportunities/notifications, partial-satisfaction modeling, UI or real source qualification.

`GET /v1/intents/{id}/external-leads` requires current `intents:read` and an active, unexpired intention owned by the credential's principal. `GET /v1/owner/intents/{id}/external-leads` uses the verified owner and the intention's active attribution agent. Foreign principals and restricted-field recipients cannot use these routes to obtain intention-scoped leads. The finite `intention_external_leads` operation shares this domain read through MCP/A2A. Owner and financial commands remain outside the agent registry.

Queries accept optional `kind=external_request|external_capability`, literal case-insensitive permitted-title/summary substring `q` (at most 200 Unicode codepoints), `limit` (1–50, default20) and `cursor`. Duplicate/unknown parameters, malformed percent encoding, raw semicolon separators and U+0000 are rejected. The raw q bound is checked before normalization; the complete raw query is capped at8192bytes, accommodating valid UTF8 filters and signed cursors. Cursors use a purpose-separated HMAC and bind environment, principal, agent, credential, owner/agent channel, current intention revision, normalized filters and limit. Tampered or differently bound cursors return400; cursors older than30minutes return410. Every page rechecks current permissions/freshness; this is a current keyset list, not a retained snapshot or durable change feed. New/removed observations may change a traversal; restart the list to discover newly inserted earlier keys.

## Public versus private approval evidence

Trusted `SourceConfig.PublicPermissionNotice` is optional and explicitly intended for public display, capped at2000bytes. Without a nonblank notice and permission to expose `canonical_url`, a source produces no public leads. The source's publisher name and permitted metadata remain untrusted claims. Source configuration still records private access/republication/tombstone evidence; the API neither returns nor searches those strings or the operator endpoint. A notice records publication configuration, not a platform assertion that actual permission or legal authority was verified.

Normal raw migration026 adds only the narrowly granted `external_leads_for_intention` security-definer projection. App roles cannot select source tables/configuration directly. The projection independently enforces current own-intention eligibility, active observation version, current field allowlist/public notice, and successful source/observation checks within24hours. Removed notices, link permissions, closed/deleted/taken-down versions and stale sources disappear even if workers lag. Public `checked_at` is the earlier source/observation check, so `fresh_until` truthfully describes their shared freshness bound.

Results identify external origin, source/version, canonical source link, publisher, public notice, observed/checked times and permitted metadata. Identity assurance and hard constraints remain `unknown`; fit is `not_assessed`. The projection hash covers public identity/version/provenance/metadata only, never private approval evidence or changing check timestamps. A lead is neither a registered participant nor an invitation target. GET makes no opportunity/event/idempotency writes or outbound request. A2A's existing POST command transport still records its separate bounded execution receipt; that is not an external opportunity or proof of work.

## Quality assessment

One domain read owns cursor/query/authority behavior for owner, REST, MCP and A2A; one safe database projection owns the public source-field boundary. The extra SQL intention checks defend the privileged function rather than introducing adapter authority. Source fetching and financial storage remain orthogonal; no fetch, model call or pair write occurs during retrieval. Public projection hashes do not reveal private configuration changes. UUID keyset pagination is deliberately a current list rather than an invented snapshot/watch guarantee. Broader matching and notification persistence remain separate behavior with their own evidence requirements.
