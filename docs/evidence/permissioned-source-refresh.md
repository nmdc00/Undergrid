# Permissioned source refresh (implementation in progress)

TDD §5.2 / threat-model source-fetch boundary. Trusted `UNDERGRID_SOURCES_FILE` contains the complete approved source configuration array. Each entry identifies an HTTPS endpoint, publisher, access/republication/tombstone evidence and explicit metadata field allowlist. Supported kinds are `capability_manifest` and `github_requests` (api.github.com repository issue endpoint plus designated labels). These strings record operator evidence; fixtures do not qualify any actual publisher or confer legal permission.

The network River coordinator reconciles the complete trusted source set and transactionally enqueues one deduplicated job per configured source. Each job calls `SourceRefresher.RefreshSource` on a dedicated queue with two workers, so one slow publisher does not consume the coordinator job timeout or block the default queue. The direct `RefreshDue` helper remains available for bounded administrative/test invocation. A session advisory lock deduplicates concurrent fetches without holding a database transaction over HTTP. A short apply transaction rechecks the exact current approval and schedule before publishing the complete snapshot: at most ten pages, 100 records/page, 1 MiB/page, 45 seconds/source; successful checks schedule six-hour refresh. Single-page ETags permit conditional revalidation; multipage feeds are fully reread because page-one ETag cannot establish freshness of later pages. Only approved feed endpoints are fetched; pagination adds numeric page parameters, never follows response URLs. Proxy use and redirects are disabled. DNS is resolved and all answers checked before dialing the selected public address, while TLS retains original hostname validation. Embedded links remain untrusted inert metadata.

Only selected title/summary/tags/timestamps/canonical-link fields are copied; GitHub bodies/comments/profiles are excluded, PR entries and nonmatching issue labels are filtered. Closed/deleted/taken-down records have metadata erased. Removing a source from configuration disables its discovery and erases observation metadata on the next refresh. Permission provenance remains in restricted worker source configuration. The eligibility view rejects observations older than 24 hours and sources without recent successful checks. No public match/ranking/API/UI integration is claimed in this slice.
